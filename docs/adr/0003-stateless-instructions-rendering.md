# 3. 坚持提示词按需直读无状态原则，拒绝过早引入内存缓存

- **状态 (Status)**: 已采纳 (Accepted)
- **日期 (Date)**: 2026-10-02
- **决策者 (Deciders)**: Ponytail 架构小组

## 背景与上下文 (Context)
`render(skillDir, mode)` 函数在每一次生成系统提示词时，会同步从磁盘读取 `skills/ponytail/SKILL.md` 并按模式裁剪。有观点提出应在内存中缓存渲染结果，以避免重复读盘。

## 架构决断 (Decision)
**坚持按需同步读盘，坚决不引入内存缓存。**
基准性能实测证据：
- 现代操作系统页缓存（Page Cache）常驻下，单次 `readFileSync` 耗时仅 0.22ms（在每次 LLM 轮次数百毫秒的网络耗时中占比小于 0.02%）；
- 引入内存缓存将带来缓存失效风险，破坏用户在不重启常驻服务的情况下直接热改 SKILL.md 即时生效的优秀体验；
- 坚决坚守 Ponytail 梯子第一阶（YAGNI）与“在 Profiler 证明存在瓶颈前绝不加缓存”的工程铁律。

## 影响与后果 (Consequences)
- **正面收益**：无状态深模块，支持免重启热改调试，代码行数零增长，无内存泄漏与脏缓存隐患；
- **妥协权衡**：每次 systemPrompt 计算消耗 0.22ms 内存读盘，实测对整体吞吐量无任何可测量负面影响。
