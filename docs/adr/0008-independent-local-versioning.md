# 0008 本地版本独立于上游参考版本

- 状态：已采纳
- 日期：2026-10-04
- 本地版本：5.0.0
- 上游参考：DietrichGebert/ponytail 4.10.3

## 背景

本仓库是面向 DeepSeek Harness 的 DSH 插件适配实现。它拥有独立的 Host/Browser 双面插件结构、Cordis 生命周期接线、DSH 数据根、客户端产物构建、真实 Web 回归和发布门禁。上游 Ponytail 主要提供行为、技能和设计语义参考，不是本地 npm 包的版本真源。

历史版本使用 `4.10.0-dsh.N` 表达跟随上游版本并附加 DSH 递增号。该规则把两个不同维度混在一个版本号里：上游参考实现的变更节奏与本地 DSH 适配的兼容性、运行时回归和发布节奏并不相同。

## 决策

从本地 `5.0.0` 开始，`@wenaixi/dsh-ponytail` 使用独立的标准 SemVer `x.y.z`。本地版本由 `package.json.version` 唯一决定，并由 `scripts/version.mjs` 读写。

上游版本只作为参考快照记录在 README、CHANGELOG 和维护文档中。上游发布新版不会自动改变本地版本，也不会触发本地依赖升级、构建或发布。是否吸收上游变化必须经过本地兼容性评估、实现、测试和文档更新。

## 版本含义

- 本地 patch/minor/major：由 DSH 适配实现、公开行为、配置格式、客户端契约、兼容性或发布策略决定。
- 上游参考版本：表示本地实现最近核对过的上游行为来源，不表示本地代码与上游所有宿主实现相同。
- 本地 `5.0.0` 不表示上游已经发布 `5.0.0`，也不承诺上游 API 与本地 DSH API 兼容。

## 迁移影响

历史 `4.10.0-dsh.N` 版本仍保留在 CHANGELOG 和 Git 历史中，用于追溯，不再由版本脚本生成。现有 DSH 配置格式继续按当前实现读取；本地版本主版本变化不自动等价于配置格式破坏，具体迁移要求以每个版本的 CHANGELOG 为准。

安装、升级和卸载的宿主生命周期仍需遵守真实运行时边界：从零安装后当前页面可能需要刷新；已经激活或导入失败的旧版本升级后应重启宿主；卸载后已打开页面可能暂留旧 UI，刷新或重启后完全消失。

## 被拒绝的方案

- 继续生成 `-dsh.N`：无法表达本地适配独立的兼容性和发布节奏。
- 自动联网把上游版本写入本地 manifest：会让构建和发布结果依赖外部状态，且无法替代兼容性验证。
- 把上游版本作为 npm 包版本真源：混淆参考实现与 DSH 适配的公开契约。

## 维护要求

每次更新上游参考时，记录新的参考版本、核验日期、链接和实际吸收的差异；不因仅更新参考记录而自动改本地版本。版本脚本不得生成旧的 `-dsh.N` 格式，也不得自动执行 push 或 publish。
