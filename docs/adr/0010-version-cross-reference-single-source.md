# 0010 版本对照的唯一落点是项目记忆库

- **状态 (Status)**: 已采纳 (Accepted)
- **日期 (Date)**: 2026-10-06

## 背景与上下文 (Context)

[ADR-0008](0008-independent-local-versioning.md) 定下「本地版本独立于上游参考版本」，并在同一份
ADR 里写下两条落点：上游版本作为参考快照记录在 README、CHANGELOG 和维护文档中。

实际执行时出现了三个问题：

1. **版本号在多处硬编码**。本地当前版本 `5.1.0` 同时出现在 README 头部引言、README 版本策略段、
   CHANGELOG 顶部提示、ADR-0008 正文、ADR-0004 与 ADR-0009 的验收记录里。每次发版要改五处，
   漏改一处就是文档在撒谎。
2. **README 不是版本记录的正确落点**。README 是给 npm 页面上的读者看的安装与使用说明，
   上游参考版本号对它没有决策价值；真正需要「本地 5.1.0 对应上游参考 4.10.3、核验于某日」
   的是本仓库的维护者，那是 `CLAUDE.md` 的职责（该文件被 .gitignore 排除，不随包发布）。
3. **ADR 是决策快照，不随发版更新**。`CLAUDE.md` 的维护规则已写明「ADR 一律新建编号文件修订旧决策，
   不原地改写历史结论」，因此 ADR-0008 里的 `5.0.0` 必须保持不动，它是当时的决策输入。

## 架构决断 (Decision)

1. **版本对照只写在 `CLAUDE.md` 的「项目与版本」段**，形状固定为：
   本地发行版本 + 上游参考版本 + 核验日期 + 「上游发布不会自动决定本地版本号」这一条。
2. **README 不再承载版本对照**。README 保留「本地版本与上游参考独立维护」这一句定性说明
   与上游仓库链接，具体版本号由 npm 页面与 CHANGELOG 呈现。
3. **`scripts/docs-verify.mjs` 的门禁随之调整**：
   - 从 README 的必需文本中移除 `4.10.3`；
   - 改为断言 `docs/adr/0008-independent-local-versioning.md` 含 `4.10.3`（ADR 作为
     参考快照的历史记录必须留存），并断言它同时含 `5.0.0` 与 `独立`、`不再由版本脚本生成`；
   - 新增：README 必须含「独立维护」这一定性表述，防止把版本策略整个删掉；
   - 新增：`CHANGELOG.md` 顶部提示必须含 `4.10.3`，它是发版时唯一随包分发的参考快照记录；
   - 新增：`CLAUDE.md` 若存在，必须含「上游参考」与「独立演进」字样，
     缺失即判失败（记忆库被误删或漏更新时门禁会响）。
4. **本地版本号不得在文档里硬编码**。文档提及当前版本时一律指向 `package.json`。
   `package.json.version` 是唯一真源，由 `scripts/version.mjs` 读写。

## 影响与后果 (Consequences)

- **正面收益**：发版时只有 `package.json.version` 一处需要改；版本对照不再散落在五份文件里；
  npm 页面上的 README 也不再出现会立刻过期的核验日期。
- **妥协权衡**：`CLAUDE.md` 被 .gitignore 排除，克隆仓库的外部贡献者看不到版本对照。
  他们看 ADR-0008 与 CHANGELOG，两者都保留参考快照。
- **文档结构变化**：README 顶部与版本策略段删去具体版本号，CHANGELOG 顶部保留。

## 被拒绝的方案

- **只删 README 里的日期、保留版本号**：版本号仍会在多处漂移，等于没解决。
- **把版本对照搬进 CHANGELOG 顶部（只删 README 一处）**：CHANGELOG 顶部已经承担「本地版本 +
  上游参考 + 核验日期」，再加一份 README 副本等于两个会漂移的落点。
- **给版本号加自动替换脚本**：项目已有 `scripts/version.mjs` 与 `docs-verify.mjs`，
  文档里不写版本号比写替换脚本更省事，也不引入新的失败面。
